## Policy Boundary

This policy tells reviewers and local operators how to handle generated registry sidecars during the R3 migration window. It covers review, regeneration, drift handling, and authority-state boundaries for generated sidecars and hand-authored YAML registries.

Generated sidecars are checked non-human-editable artifacts. Hand-authored YAML remains valid during the migration window. This policy does not approve YAML removal, generated sidecar authority, a source-authority flip, rollback rehearsal completion, or final migration readiness.

## Authority States

| State | Editable source | Generated sidecar role | Reviewer action | Operator action |
| --- | --- | --- | --- | --- |
| `yaml-authoritative` | Hand-authored YAML registry remains valid source. | Checked transition evidence only. | Review generated diffs as derived evidence, not replacement authority. | Run compatibility and migration checks; do not edit generated YAML. |
| `parity-candidate` | Hand-authored YAML remains valid while Markdown/profile parity is evaluated. | Checked artifact used for comparison. | Require registry, graph, metadata, and validation deltas to be equivalent, intentional, or blocking. | Run `migration-check` and resolve blocking drift at source. |
| `generated-checked` | Markdown and type profile may be treated as candidate editable inputs for checked evidence. | Checked artifact remains non-human-editable. | Review generated bytes through the policy and command evidence. | Regenerate through CLI write mode when source changes require new bytes. |
| `blocked` | Current source state is not accepted for promotion. | Missing, stale, or drifting artifact blocks review. | Reject promotion or approval claims until fixed evidence exists. | Restore source-control bytes or regenerate from source; rerun checks. |

`generated-authoritative` is not available under this policy. It requires a later separate approval record after all R3 evidence gates, including rollback and final evidence, are accepted.

## Reviewer Policy

Reviewers treat generated sidecar diffs as deterministic checked evidence. A generated sidecar diff is reviewable only when the artifact path, metadata, and generated marker follow the R2 contract and the surrounding docs keep YAML compatibility intact.

Blocking review conditions:

- The diff suggests generated sidecars are human-editable source.
- The diff removes, weakens, or bypasses the hand-authored YAML compatibility path.
- The diff treats generated sidecars as authoritative before a separate source-authority approval.
- Required `generated.*` metadata is missing, non-deterministic, absolute-path based, stale, or inconsistent with the source document or type profile.
- Migration comparison reports blocking drift in registry, graph, metadata, or validation dimensions.
- A missing or stale generated artifact is corrected by hand-editing generated YAML instead of regenerating or restoring bytes.

Acceptable review outcomes:

| Signal | Meaning | Approval posture |
| --- | --- | --- |
| All dimensions `equivalent` | Manual and generated outputs match after normalization. | Accept inside the current state boundary. |
| Metadata `intentional` in `yaml-authoritative` state | Manual YAML lacks generated metadata while checked generated metadata is valid. | Accept only as transition evidence. |
| Any dimension `blocking` | Unexplained drift exists. | Reject until the source, profile, artifact, or approval rationale is corrected. |
| Missing or stale artifact | Checked evidence cannot be trusted. | Reject until check mode passes after restore or regeneration. |

Reviewers must not require rollback rehearsal or final migration evidence for BEL-1241 approval. Those are follow-up work unless the current docs claim they are already complete.

## Operator Workflow

Run these commands from the repository root after installing dependencies and building when needed.

| Purpose | Command |
| --- | --- |
| Build CLI | `npm run build` |
| Validate the R0 YAML compatibility path | `npm run validate:fixture` |
| Check the selected migrated fixture | `npm run migration:check` |
| Check a generated sidecar without writing bytes | `node dist/markdowntrace/cli.js derive-sidecar --document fixtures/r1-link-backed-entity-syntax/minimal-link-backed-execution-spec.md --type-profile fixtures/r1-link-backed-entity-syntax/minimal-type-profile.yaml --check` |
| Regenerate the selected generated sidecar when source inputs intentionally changed | `node dist/markdowntrace/cli.js derive-sidecar --document fixtures/r1-link-backed-entity-syntax/minimal-link-backed-execution-spec.md --type-profile fixtures/r1-link-backed-entity-syntax/minimal-type-profile.yaml` |
| Check diff hygiene | `git diff --check` |

Regeneration is allowed only through the Markdown Trace CLI. Operators must not patch generated YAML by hand. If source Markdown or type profile changes are intentional, regenerate the checked artifact from those inputs, then rerun check mode and migration checks.

## Drift Handling

| Drift signal | Likely cause | Required response | Approval impact |
| --- | --- | --- | --- |
| Missing generated artifact | Artifact was not checked in or was removed. | Regenerate through CLI write mode or restore expected source-control bytes, then rerun check mode. | Blocking until resolved. |
| Stale generated artifact | Source Markdown, type profile, or generator output differs from checked bytes. | Regenerate from source or restore prior source/artifact pair; never hand-edit generated YAML. | Blocking until check mode passes. |
| Blocking registry drift | Manual and generated registry facts differ without approved rationale. | Fix the editable source, type profile, or manual YAML according to the current authority state. | Blocking. |
| Blocking graph drift | Derived graph projection differs unexpectedly. | Inspect entity and edge facts; fix source or registry inputs, then rerun migration check. | Blocking. |
| Blocking metadata drift | Generated metadata does not match R2 contract or current source/profile bytes. | Regenerate through CLI write mode and verify metadata is repository-relative and deterministic. | Blocking. |
| Blocking validation drift | Manual and generated validation outcomes differ. | Fix the source/profile/registry cause before requesting review. | Blocking. |
| Intentional metadata absence | Manual YAML has no `generated.*` metadata while state is `yaml-authoritative`. | Confirm generated metadata is valid and comparison classifies the delta as intentional. | Non-blocking transition evidence. |

If drift cannot be resolved without changing registry semantics, generated sidecar serialization, command behavior, or authority state, stop and request a new scoped decision before changing code or policy.

## Authority Boundary Checklist

- Generated sidecars are checked non-human-editable artifacts.
- Hand-authored YAML remains valid during the migration window.
- Check mode must not write, create, or rewrite generated artifact bytes.
- Write mode may regenerate checked artifacts from source inputs when source changes are intentional.
- Reviewers approve or reject evidence, not a source-authority flip.
- Operators recover by source-control restore or deterministic regeneration, not manual generated YAML edits.
- Rollback rehearsal and final migration readiness remain separate follow-up gates.
